SCENE 1 — HOOK (0–3s)
================================================================================

Purpose:
  Establish the pain — AWS infrastructure is overwhelming.

Visuals:
  - Dark canvas
  - AWS service icons (EC2, RDS, S3, Lambda, ALB) appear scattered and
    overlapping with messy hand-drawn arrows between them
  - Slight jitter/shake applied to the group

On-screen text:
  "Cloud infrastructure shouldn't be this hard."

Animation ideas:
  - Icons spring-in at random positions (staggered 10–15 frames each)
    via spring({ damping: 8 }) — bouncy, chaotic feel
  - Group applies a rotate wobble via interpolate — unsettled feel
  - Text fades in at frame 30 with Easing.out(Easing.quad)

Transition to next:
  fade() — 10 frames — soft reset

================================================================================
 — INPUT (3–7s)
================================================================================

Purpose:
  Show the product entry point — describe your app in plain English.

Status: BUILT — src/Scene2Input/
Duration: ~9s at 30fps

Phases:

  Phase A — App UI fades in
    The full DrawToCloud app interface appears: dark canvas, navbar with the
    "drawtocloud" wordmark and a blue "New Architecture" button, navigation
    tabs, and side panels showing a chat interface on the left and template
    cards on the right.

  Phase B — Zoom to button
    Camera zooms in toward the "New Architecture" button, centering it on
    screen.

  Phase C — Cursor clicks button
    A white arrow cursor slides in and clicks the "New Architecture" button
    with a subtle press animation.

  Phase D — Modal appears
    Camera zooms back out. A "Describe your app" modal springs into view over
    a dimmed backdrop. It contains a textarea, expected users card grid, uptime
    options, AWS region selector, monthly budget field, and a "Generate
    Architecture" button.

  Phase E — Form fills in
    The textarea types itself out: "A scalable SaaS web app with Postgres DB,
    Redis cache, and a global CDN for asset delivery." The "MVP / Just
    exploring" card pulses blue, then the "Standard" uptime card pulses blue.

  Phase F — Scroll reveals more fields
    The modal scrolls down to reveal the AWS region selector (us-east-1 checks
    itself in) and a monthly budget field that types "500".

  Phase G — Cursor clicks "Generate Architecture"
    A cursor slides down to the "Generate Architecture" button and clicks
    with a press animation. The button stays solid blue.

  Phase H — Fade to black
    After a brief pause, the modal and everything on screen fades to black
    over ~1 second, with a subtle upward drift. Clean cut to the next scene.

Files:
  src/Scene2Input/index.tsx     — zoom orchestration, fade-to-black transition
  src/Scene2Input/AppShell.tsx   — static app recreation (navbar + panels)
  src/Scene2Input/Cursor.tsx     — animated SVG pointer (2 cursors: button + generate clicks)
  src/Scene2Input/Modal.tsx      — modal spring entrance + all form content, typewriter, scroll
  src/Scene2Input/CanvasArea.tsx — empty canvas with dot grid + status bar
  src/Scene2Input/ChatPanel.tsx  — left chat panel with messages + input
  src/Scene2Input/TemplatesPanel.tsx — right panel with template cards

Transition to next:
  Fade to black → cut to Scene 3

================================================================================
REMOTION RULES (key constraints)
================================================================================

- ALL animations driven by useCurrentFrame() — no CSS transitions/animations
- No Tailwind animation classes (will not render correctly)
- Spring configs:
    smooth  = { damping: 200 }          — subtle reveals
    snappy  = { damping: 20, stiffness: 200 }  — UI elements
    bouncy  = { damping: 8 }            — playful entrances
- Always clamp interpolate with extrapolateLeft/Right: "clamp"
- Use TransitionSeries for scene transitions (not manual Sequence overlap)
- Icons from frontend/lib/awsIcons.tsx (copied to each scene folder)
