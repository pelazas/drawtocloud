# DrawToCloud v1.2.0

**Release Date:** 2026-05-04

## Overview

v1.2.0 is a reliability and observability release focused on chat/WebSocket stability and rate-limit handling. It fixes several race conditions around logout and WebSocket state, adds structured rate-limit error support, and hardens chat delivery during reconnections.

---

## What's New

### Rate-Limit Observability
- **Structured rate-limit errors** — Backend classifies provider 429s as `LlmProviderRateLimitError` and emits typed error payloads
- **Frontend rate-limit UI** — Recognizes rate-limit errors and shows product-level copy instead of generic failure messages
- **Documentation updates** — `platform-docs.md` and `data-reference.md` updated with the new error contract

### Chat & WebSocket Reliability
- **`sendWhenOpen` API** — Queues chat messages while the WebSocket is connecting, delivering them once the socket opens (prevents message drops during reconnect)
- **Chat availability gating** — Chat input is disabled while the WebSocket is disconnected, with a visible reconnect reason
- **Subscription replay** — Pre-open messages (e.g., `subscribe_project` sent before connection completes) are automatically replayed once connected
- **WS-chat race fix** — Resolves race condition where chat messages could be lost or sent to the wrong session during reconnection

### Logout Stability
- **Logout redirect guards** — Fixes hydration mismatch and project-list race conditions during logout
- **State cleanup on logout** — Pipeline and workspace state are properly reset during logout redirect
- **Unified redirect marker** — Single source of truth for suppressing duplicate logout redirects

### Security
- **CSP fix for IP geolocation** — Added `https://ipapi.co` to `connect-src` directive so the app can fetch user region for cost estimation

---

## Bug Fixes
- Chat messages no longer drop when sent during WebSocket reconnection
- Logout no longer triggers hydration errors or stale project-list renders
- Rate-limit errors are surfaced with actionable copy instead of generic "Something went wrong"
- Pre-open WebSocket messages are replayed after connection instead of being lost
