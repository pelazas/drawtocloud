SCENE 1 — HOOK (0–3s)
================================================================================

Purpose:
  Establish the pain — AWS infrastructure is overwhelming.

Visuals:
  - Dark canvas
  - AWS service icons (EC2, RDS, S3, Lambda, ALB) appear scattered and
    overlapping with messy hand-drawn arrows between them
  - Slight jitter/shake applied to the group

On-screen text:
  "Cloud infrastructure shouldn't be this hard."

Animation ideas:
  - Icons spring-in at random positions (staggered 10–15 frames each)
    via spring({ damping: 8 }) — bouncy, chaotic feel
  - Group applies a rotate wobble via interpolate — unsettled feel
  - Text fades in at frame 30 with Easing.out(Easing.quad)

Transition to next:
  fade() — 10 frames — soft reset

SCENE 2 — INPUT (3–7s)
================================================================================

Purpose:
  Show the product entry point — describe your app in plain English.

Status: BUILT — src/Scene2Input/
Duration: 120 frames (4s) at 30fps

Phases:

  Phase A — App UI (frames 0–20)
    Full app shell fades in: navbar with drawtocloud wordmark, blue NEW
    ARCHITECTURE button, TEMPLATES / MY DESIGNS / AUTO LAYOUT nav items,
    right-side SAVE + GENERATE TERRAFORM buttons, left panel with chat
    suggestion pills, and the empty dark canvas.
    Fade-in: interpolate(frame, [0, 18], [0, 1]).

  Phase B — Zoom In (frames 20–42)
    Camera zooms 1×→1.9× toward the NEW ARCHITECTURE button (center ~192, 29).
    Uses translateX/Y + scale so the button lands at screen center (960, 540).
    Easing: Easing.inOut(Easing.quad).

  Phase C — Cursor + Click (frames 38–70)
    White arrow cursor slides from (1520, 780) → (965, 546) using
    Easing.out(Easing.cubic), arriving at frame 50. Click fires at frame 52:
    cursor shrinks to 0.7× and the NEW ARCHITECTURE button scales to 0.92×,
    both bouncing back. Cursor fades out by frame 70.

  Phase D — Zoom Out + Modal (frames 58–82)
    Zoom eases back to 1× (frames 58–76). At frame 65 the "Describe your app"
    modal springs in: spring({ damping: 28, stiffness: 120 }), scale 0.94→1 +
    backdrop fades to rgba(0,0,0,0.55). Modal is a faithful recreation of the
    actual product UI: textarea, AI codebase helper row, Expected Users 2×2
    card grid, Uptime card list, Cancel + Generate Architecture footer.

  Phase E — Form Fill (frames 82–120)
    High-pace typewriter fills the textarea (frames 84–116):
      "A scalable SaaS web app with Postgres DB, Redis cache,
       and a global CDN for asset delivery."
    Blinking cursor: Math.floor(frame / 12) % 2 === 0.
    At frame 102: "MVP / Just exploring" card pulses blue via
      spring({ damping: 12, stiffness: 300 }).
    At frame 110: "Standard" uptime card pulses blue the same way.

Files:
  src/Scene2Input/AppShell.tsx  — static app recreation (navbar + panels)
  src/Scene2Input/Cursor.tsx    — animated SVG pointer + click
  src/Scene2Input/Modal.tsx     — modal spring entrance + all form content
  src/Scene2Input/index.tsx     — zoom orchestration, phase composition

Transition to next:
  fade() — 8 frames — seamless

================================================================================
REMOTION RULES (key constraints)
================================================================================

- ALL animations driven by useCurrentFrame() — no CSS transitions/animations
- No Tailwind animation classes (will not render correctly)
- Spring configs:
    smooth  = { damping: 200 }          — subtle reveals
    snappy  = { damping: 20, stiffness: 200 }  — UI elements
    bouncy  = { damping: 8 }            — playful entrances
- Always clamp interpolate with extrapolateLeft/Right: "clamp"
- Use TransitionSeries for scene transitions (not manual Sequence overlap)
- Icons from frontend/lib/awsIcons.tsx (copied to each scene folder)
